## 4. NF-01逐项修复

### 4.1 同步公开路由

通过临时FastAPI应用真实注册`api.routers.video.router`，使用
`httpx.ASGITransport`请求`POST /api/video/generate/sync`。仅覆盖依赖注入的Core，
未直接调用Router函数。

成功合同固定为HTTP 200及既有
`success/message/video_url/duration/file_size`响应；断言不含`task_id`或`job_id`，
Core只调用一次，且同步路由不创建旧TaskManager任务。

### 4.2 Provider失败

公开同步路由使用离线FailingCore抛出既有`RuntimeError`，固定当前HTTP 500及
`detail`响应，断言原Core只调用一次，TaskManager不创建第二任务。

Facade专项测试令持久化叶子submitter抛出同一异常对象，断言异常原样传播、
持久化路径仅调用一次、旧复合submitter零调用，证明无回退或双提交。

### 4.3 `submission_unknown`

使用既有`ErrorCategory.SUBMISSION_UNKNOWN`，由持久化叶子submitter返回给Facade。
断言结果保持该既有状态类别，持久化路径恰调用一次，旧复合路径零调用，未把
不确定提交当成确定未提交，也未重提或回退。

### 4.4 输入资产不存在或不可用

真实注册`api.routers.media_jobs.router`，分别由离线service fake抛出既有
`AssetNotFoundError`和`AssetUnavailableError`。两者均固定当前HTTP 422及
`invalid_asset`脱敏错误体；断言请求只到达一次输入校验，响应不含绝对Windows
路径、Traceback或Provider信息。

fake在抛错后不执行Repository或Provider，测试应用也未注册第二任务事实源，因而
不存在Provider提交、第二任务或部分双写。

### 4.5 旧任务列表

真实注册`api.routers.tasks.router`并请求`GET /api/tasks`。分别冻结空列表及一个
运行中旧任务：

- HTTP 200；
- 顶层始终为JSON数组；
- `task_id/status/task_type`保持旧Task模型；
- TaskManager按`status=None, limit=25`调用一次；
- 不含SQLite的`job_id`，不改写旧任务ID。
