# AI Media Platform—阶段02-D素材与输出资产独立只读验收报告

## 1. 验收结论

**不通过，存在阻断问题。**

本次独立验收确认阶段02-D的大部分基础能力已经实现，冻结基线、迁移、270项离线测试、Ruff、路径安全基本面和公共API脱敏均可复现；但存在1个P0阻断缺陷和3个P1必要修复缺陷：

1. **P0 D-01：生产Worker中的历史legacy只读回退实际不可达。** `worker_cli.py`始终向Executor装配`asset_service`；`executor.py::_build_parameters`只要`asset_service is not None`就把输入值当UUID交给AssetService，只有`asset_service is None`才调用`ManagedAssetResolver`。冻结点之前的路径型任务没有数据库资产关系，生产装配下会因UUID校验失败，无法按契约只读兼容。实现没有基于历史记录或关系表可靠区分新旧任务。验收任务明确规定“若无法证明新旧任务被可靠区分，应判为阻断性缺陷”。
2. **P1 D-02：输出资产登记成功后终态CAS丢失会删除已登记正式对象。** `register_output_group`已在事务中提交资产、关系和兼容投影；随后`_finish`若抛`LeaseLostError`，统一异常分支调用`_remove_outputs`，其AssetService分支会删除这些已经登记的对象，留下`available`资产及输出关系指向缺失文件。
3. **P1 D-03：非租约类输出登记失败没有即时补偿。** 文件已发布后，`register_output_group`若因数据库错误、约束错误或关系写入错误抛出非`LeaseLostError`异常，当前代码不会调用`discard_unregistered`。对账能事后报告孤儿，但普通可捕获失败没有履行严格契约要求的明确补偿；现有测试没有覆盖此失败点。
4. **P1 D-04：物理清理存在检查—删除—数据库删除竞态及失败窗口。** `physical_cleanup`先独立查询引用数，再删除文件，再由`purge_record`重新查询并删除数据库行。若两次检查之间新增任务引用，或文件删除后数据库操作失败，会留下仍受引用/仍存在的资产记录但字节已丢失。现有测试只覆盖“调用前已有引用”的静态拒绝，未覆盖竞态和数据库失败。

因此阶段02-D不能进入本地提交前审阅；下一步只能由项目负责人另行授权02-D范围内的必要修复，并在修复后重新独立只读复验。本报告不授权也未执行任何修复。

## 7. Local Store与路径安全

`LocalAssetStore`以服务端object key工作；拒绝空值、NUL、反斜杠、绝对路径、Windows drive/UNC、`.`、`..`及空段。每次读写删重新resolve并检查根内边界，检查中间符号链接和最终符号链接。写入采用唯一UUID `.part`、分块计算大小/SHA256、`fsync`和同卷`replace`，错误清除临时对象。

现有测试覆盖危险object key、超限、唯一临时文件及符号链接逃逸。旧`/api/files`也以项目固定根、逐段匹配、`resolve(strict=True)`及`relative_to`拒绝穿越/前缀碰撞/符号链接逃逸，错误脱敏。未发现公共API暴露Store根或object key。

结论：通过；未执行junction专项系统级测试，符号链接行为由现有Windows环境测试覆盖。

## 8. 上传、注册及并发幂等

`POST /api/assets`只接受UploadFile与独立`Idempotency-Key`，asset UUID及object key均由服务端生成；不接受路径、URL、backend或输出kind。Service流式写入并校验大小、扩展/MIME和最低签名，再创建数据库记录。数据库唯一幂等键是并发最终防线。

并发测试真实执行同键同内容并确认一个资产记录和一个正式对象；冲突测试确认不同内容返回冲突且败方文件被补偿。公共API不提供任意本地路径导入。

结论：通过。

## 10. 新任务UUID与历史兼容

新任务生产装配下要求合法UUID、`available + input`、I2V image类型且Store对象存在；任务行和输入关系在同一事务写入。路径字符串及伪造UUID被拒绝，新任务不会写路径型asset_id。

但历史兼容不成立：

```text
worker_cli.run_worker
  -> 始终构造 AssetService
  -> RecoverableComfyUIExecutor(asset_service=asset_service)
  -> _build_parameters: asset_service != None
  -> resolve_local_input(asset_id)
  -> require_asset_uuid(历史路径字符串)
  -> 失败
```

legacy `ManagedAssetResolver`只在测试或显式不装配AssetService时可达，不是“基于历史记录语义”的可靠判别。冻结点之前的任务没有`media_job_assets`关系；代码没有按关系存在性或迁移时点选择回退。

结论：不通过，P0 D-01。

## 11. Worker、重试和输出终态链路

新任务输入通过AssetService/Store解析，Provider只获得内部受控路径；输出下载后写唯一对象、计算元数据、事务登记资产与关系并投影`output_metadata`，然后才尝试任务成功终态。重试复制输入关系、不复制输出关系。

缺陷：

- 历史任务生产回退不可达（P0 D-01）；
- 已登记后终态租约丢失会删除已登记对象（P1 D-02）；
- 非租约数据库/关系登记失败不补偿已发布对象（P1 D-03）；
- 发现既有输出关系时直接尝试成功终态，没有验证关联资产仍available且对象存在；若此前触发D-02，恢复可把缺字节任务置为成功。

因此完整“输入→输出→关系→成功终态”一致性不通过。
