## 5. Facade接入前后真实调用链

接入前：

```text
POST /api/media/jobs
→ MediaJobRequest
→ MediaJobApplicationService.create一次
→ SQLite和既有资产关系
→ MediaJobResponse
```

接入后：

```text
POST /api/media/jobs
→ MediaJobRequest
→ SubmissionRequest
→ CompatibilitySubmissionFacade
→ persistent_leaf
→ MediaJobApplicationService.create一次
→ SQLite和既有资产关系
→ 既有MediaJobResponse
```

Router先验证显式`Idempotency-Key`，再把已通过公开Schema的workflow、公开参数和
`asset_id`无损规范化。Facade按既有E1规则重新构造`MediaJobRequest`并只调用
persistent submitter。该submitter源码中只有一个`service.create`调用点，没有
`try/except`回退；legacy submitter只会明确拒绝，不具备旧执行能力。
