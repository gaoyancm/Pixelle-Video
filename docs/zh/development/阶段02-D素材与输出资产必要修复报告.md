## 5. D-01：生产Worker输入分流

### 根因

首次实现以“是否装配AssetService”选择新资产或legacy解析；生产Worker始终装配AssetService，导致历史路径分支不可达。

### 修复

- `worker_cli._build_executor`成为生产Worker使用且可直接离线测试的同一装配函数，仍装配AssetService；
- Executor先按`job_id`查询持久化输入关系；
- 有关系时只按关系读取`available + input`资产，兼容JSON中的路径值不能覆盖关系；
- 无关系时才进入legacy解析；
- legacy只接受单一受控历史文件名，显式拒绝UUID形状、伪UUID、绝对路径、drive、UNC、斜杠、反斜杠、混合分隔符、越界和符号链接逃逸；
- legacy读取不创建资产、不写关系、不改写任务；
- 历史重试无输入关系时仍按同一受控legacy路径解析；
- 新任务与重试关系写入继续要求可用资产，并以条件更新和关系写入置于同一事务。

### 生产装配矩阵

| 场景 | 结果 |
| --- | --- |
| 生产装配＋新任务输入关系 | 通过关系和Store解析 |
| 同一生产装配＋合法历史路径 | 通过legacy根内只读解析 |
| 历史任务重试 | 无新关系，继续受控解析 |
| 无关系＋UUID/伪UUID | 拒绝，不降级 |
| 无关系＋危险路径/符号链接 | 拒绝 |
| 有关系＋兼容字段为路径 | 关系优先，路径不能绕过 |
| 新任务API路径型`asset_id` | 既有API测试继续拒绝 |

## 6. D-02：已提交输出与终态恢复

### 根因

输出资产、关系和兼容投影提交后，成功终态CAS/租约失败仍进入“删除未登记对象”分支。

### 修复

- Executor显式记录输出组是否已经登记；
- 只有登记前的租约/CAS失败才补偿本轮未登记对象；
- 登记成功后任何`_finish`租约/CAS失败均保留资产、关系和Store对象；
- 恢复发现既有输出关系时，先验证关系position完整、资产为`available + output`、Store对象存在，以及兼容投影的ID、size、SHA256、MIME一致；
- 验证通过才幂等完成成功终态；
- 对象缺失、资产不可用或投影不一致时不得成功，进入`output_missing`失败；
- 重复恢复不重复登记、不删除正式对象。

## 7. D-03：登记结果分类与安全补偿

### 根因

首次实现未区分普通数据库异常发生在提交前、提交后还是提交结果未知，也未对非租约类登记失败统一即时补偿。

### 修复协议

`register_output_group`使用本次预生成的稳定资产ID、任务ID和输出投影分类：

1. `not_committed`：事务回滚，Executor只删除本次尚未登记对象，并将任务置为失败；
2. `committed`：查询确认资产、全部关系和投影已提交，保留正式对象并继续终态；
3. `unknown`：若出现部分持久化事实或无法安全判断，禁止删除，释放任务等待恢复/对账。

资产写入、关系写入、投影写入、flush、commit前失败均进入统一路径。提交后连接错误通过新会话查询确认；部分事实不会被猜测性补偿。多输出组在单一事务内登记，任一关系失败时全部回滚并补偿本次全部未登记对象。

### 失败点矩阵

| 失败点 | 数据库 | Store | 任务 |
| --- | --- | --- | --- |
| 资产写入失败 | 无输出资产/关系 | 删除本次对象 | failed |
| 关系写入失败 | 整组回滚 | 删除本次对象 | failed |
| 投影写入失败 | 整组回滚 | 删除本次对象 | failed |
| flush/commit前失败 | 无登记事实 | 删除本次对象 | failed |
| commit报错、查询证实已提交 | 资产/关系/投影保留 | 保留 | 可继续成功终态 |
| commit报错、查询证实未提交 | 无登记事实 | 删除本次对象 | failed |
| 部分事实 | 保留可审计事实 | 不删除 | 保持可恢复、不得伪造成功 |
| 多输出第二关系失败 | 无部分成功组 | 删除本次全部对象 | failed |

## 8. D-04：物理清理并发和失败安全

### 根因

首次实现的引用检查、删文件和删记录是分离操作；检查后可新增引用，且删文件后数据库删除失败会留下仍显示`available`的缺字节记录。

### 修复协议

- `claim_cleanup`以数据库条件更新取得清理权：资产必须处于既有可清理状态且`NOT EXISTS`任何任务关系；
- 取得清理权时先提交`disabled`状态，使内容下载、任务输入、重试复制及新关系写入拒绝；
- 新任务和重试复制以资产行条件更新取得关系写入权，与清理更新竞争同一行；清理权与新引用不能同时成功；
- 输出关系登记显式要求`available + output`；
- 取得清理权后才删除Store对象；
- 最终数据库删除再次要求`disabled`且零引用；
- 文件删除失败时记录保持`disabled`；为防活跃清理者被并发接管，带对象的失败清理在一分钟后才允许重试；
- 文件已删而数据库删除失败时记录保持`disabled`且可立即重试最终删除；
- 文件不存在和记录已删除均为幂等完成；
- 未新增公开物理删除端点或后台清理器。

### 并发与失败矩阵

| 场景 | 结果 |
| --- | --- |
| 清理前已有引用 | 拒绝，记录和对象保留 |
| 清理权取得后新增输入关系 | 拒绝 |
| 清理权取得后下载 | 拒绝 |
| 两个清理权请求 | 只有首个条件更新成功 |
| 清理与新任务关系并发 | 只有一方成功 |
| 文件删除失败 | `disabled`、对象保留、可延迟重试 |
| 文件已删、DB删除失败 | `disabled`、对象缺失、可立即重试 |
| 失败后重试 | 幂等完成 |
| 非可用输出资产关系 | 拒绝 |
