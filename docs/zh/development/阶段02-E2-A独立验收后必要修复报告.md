## 4. NF-E2A-01：Facade 唯一实例化门禁

### 4.1 修复内容

新门禁对 Python AST 建立导入绑定并只统计真实的 `ast.Call`：

- 支持 `from ... import CompatibilitySubmissionFacade`；
- 支持 `from ... import CompatibilitySubmissionFacade as Facade`；
- 支持 `import ...facade as migration` 后的模块属性调用；
- 支持 `import pixelle_video as pv` 后的多级模块属性调用；
- 支持一步、多步及元组/列表结构化赋值传播并以固定点迭代防止别名循环；
- 对可能指向Facade但无法可靠解析的动态赋值调用失败关闭；
- 排除仅注解、字符串、未调用属性等非实例化表达式。

真实仓库扫描结果严格等于：

```text
api/routers/media_jobs.py::_submit_create_through_facade
```

因此门禁证明的是“全仓唯一实例化位置”，而不只是某一种直接导入拼写。

### 4.2 抗绕过证据

负向 AST 样例覆盖并拒绝：

1. Facade 别名导入后实例化；
2. facade 模块别名属性实例化；
3. 顶层包别名的多级属性实例化；
4. 一步及两步赋值别名；
5. 含真实第二实例化点的别名循环；
6. 无法可靠解析的Facade能力动态赋值；
7. Facade元组拆包、属性转移及动态选择调用。

另有非调用正向样例，证明门禁不会把类型注解、字符串或仅取属性误判为实例化。

## 5. NF-E2A-02：入口可达闭包内单次 create 门禁

### 5.1 修复内容

新门禁从公开入口 `create_media_job` 出发，构建同模块本地 helper 的可达调用闭包：

- 按参数名及注解识别 `MediaJobApplicationService` 绑定；
- 通过位置参数和关键字参数传播 service 绑定；
- 传播同模块helper的一步、多步赋值别名；
- 传播`service.create`局部方法别名及再次转赋值；
- 按实际调用点统计所有可达 helper 及嵌套闭包中的 `MediaJobApplicationService.create`；
- 同时传播service对象能力和`service.create`方法能力，支持位置、关键字及多层helper；
- 同一helper的多个调用点分别累计；受控能力循环失败关闭，无受控能力循环安全终止；
- 忽略与 application service 无关的同名 `.create`；
- 对受控闭包内可能调用提交能力但无法可靠解析的动态形式失败关闭；
- 拒绝可达的 `try/except` 回退重提交流程；
- 拒绝可达的 `for`、`async for`、`while` 重试循环。

当前真实入口闭包的 `MediaJobApplicationService.create` 计数严格为 `1`。

### 5.2 抗绕过证据

负向 AST 样例覆盖并拒绝：

1. 入口直接调用一次，再经本地 helper 间接调用一次；
2. helper一步及多步赋值别名造成双提交；
3. `service.create`局部方法别名及再次转赋值造成双提交；
4. `try/except` 中异常后再次提交；
5. 循环中的重试提交；
6. 受控service的非常量动态方法调用；
7. 同一helper多个调用点及方法能力跨helper传播造成的额外提交。

另有循环 helper 图与无关对象 `.create` 的样例，证明分析会终止且不会把非目标调用计入。

## 6. NF-E2A-03：旁路允许名单真实闭包门禁

新门禁扫描明确的生产根 `api/`、`pixelle_video/`、`web/` 下全部 Python 文件，并为每个命中记录：

- 原始被调用表达式；
- 同一所属符号内的出现序号。

门禁同时解析导入别名及可静态证明的多步赋值别名，明确覆盖TaskManager、
MediaService/Core、ComfyKit、History、Provider和Adapter能力；常量危险
`getattr`直接调用及先赋值后调用被分类，别名重赋值继续追踪；受控对象上的非常量

### 6.2 抗绕过证据

负向 AST 样例覆盖并拒绝：

1. 允许名单之外新增的别名旁路调用；
2. 在已允许所属符号中额外增加一次同类调用；
3. 把真实调用移动到另一个所属符号；
4. 删除一个已声明的真实调用；
5. 名单外Provider及Adapter调用；
6. `getattr(task_manager, "create_task")()`；
7. 受控对象上的非常量动态方法调用。

因此门禁不再只验证“文件和符号存在”，而是校验精确到文件、所属符号、调用类型、被调用表达式及出现序号的真实调用闭包。
