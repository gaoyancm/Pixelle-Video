## 3. F-01：单值asset_id

### 3.1 外部契约

`MediaJobRequest`现在只公开：

- `workflow`
- 强类型`parameters`
- 可选单值`asset_id`

两个I2V工作流必须提供单值`asset_id`。其格式为1至128个`A-Z a-z 0-9 . _ : -`字符，不接受空值、空白、路径或URL。两个T2V工作流拒绝`asset_id`。

外部`asset_ids`不再是Schema字段，并因`extra="forbid"`固定返回`422 invalid_request`。同时提交`asset_id`与`asset_ids`也会因后者是额外字段而拒绝。

### 3.2 内部转换

`api/services/media_jobs.py`把合法外部单值：

```text
asset_id="managed.asset-1"
```

转换成既有内部表示：

```text
[MediaInputAsset(asset_id="managed.asset-1", role="input_image")]
```

没有修改02-A/02-B内部合同、Repository、Worker或Executor。请求哈希仍覆盖内部规范化后的资产列表，因此同一`asset_id`保持稳定幂等语义。

### 3.3 证据

新增测试覆盖：

- 两个I2V分别接受单值；
- 缺失、空值、空白、非法字符、路径字符和超长值被拒绝；
- `asset_ids`被拒绝；
- T2V的`asset_id`被拒绝；
- 数据库中确为内部单元素资产列表；
- 无效请求数据库行数保持0；
- OpenAPI含`asset_id`且不含公开`asset_ids`。

## 4. F-02：公开参数强校验

参数集中在`api/schemas/media_jobs.py::MediaJobParameters`，不在Router、Service或测试中复制工作流名称白名单。工作流名称及参数适用性继续从`WORKFLOW_SPECS`和各spec的`parameter_targets`派生。

### 4.1 参数约束表

| 参数 | 类型 | 范围/长度 | 适用工作流 | 约束来源与选择 |
|---|---|---|---|---|
| `prompt` | 严格字符串 | 1..4096字符，去除空白后非空；必填 | 全部4个 | 四个spec均有文本目标；任务契约要求非空及长度；4096为保守输入上限 |
| `negative_prompt` | 严格字符串 | 0..4096字符；可选 | 全部4个 | 四个spec均有文本目标；允许既有空负面提示 |
| `width` | 严格整数 | 1..16384 | 全部4个 | spec目标为宽度数值；采用宽松保守正整数上限，覆盖现有工作流尺寸且排除异常大值 |
| `height` | 严格整数 | 1..16384 | 全部4个 | 同width |
| `frame_count` | 严格整数 | 1..10000 | 全部4个 | spec目标为length；现有33/81工作流在范围内，排除零、负数和异常大值 |
| `seed` | 严格整数 | 0..`2^64-1` | 全部4个 | spec目标为seed/noise_seed；使用非负64位种子域 |
| `steps` | 严格整数 | 1..1000 | 仅两个I2V | 只有I2V spec包含steps；宽松保守上限避免限制现有值 |
| `cfg` | 严格有限浮点数 | 0..100 | 仅两个I2V | 只有I2V spec包含cfg；拒绝NaN/Infinity及明显异常值 |

当前公开参数中没有枚举型字段，因此没有另造枚举集合。未知字段和当前工作流不适用字段被拒绝。

宽高、帧数、steps和cfg的上限采用能够排除明显非法值且不实质限制现有工作流的宽松保守约束；没有修改工作流JSON来迎合API。

### 4.2 入库前和无副作用

Pydantic请求校验在Service和Repository调用前完成。新增响应级测试逐项检查错误类型、合法最小/最大值、低于最小、高于最大、不适用字段、未知字段、超长字符串、非有限浮点和超过32 KiB序列化体积。

首次验收复现值均固定拒绝：

- `width="not-an-integer"`
- `prompt={"nested":"object"}`
- `steps=-999`
- `cfg="bad"`

每个无效请求之后均查询真实临时SQLite Repository，确认任务数为0，没有任务或幂等记录副作用。

## 5. F-03：未知异常固定500

仅新`MediaJobRoute`增加最后顺序的未知异常映射；全部已知404、409、422和503分支保持在前。

固定响应：

```json
{
  "error": {
    "code": "internal_error",
    "message": "An internal error occurred."
  }
}
```

响应为HTTP 500和`application/json`，不拼接异常类名或原始异常文本。服务端只记录固定诊断消息，不记录异常字符串、原始幂等键、Token、请求体、资产路径或DSN。

响应级测试使用`raise_app_exceptions=False`注入包含伪秘密和本机路径的`RuntimeError`，确认响应不包含这些内容。
