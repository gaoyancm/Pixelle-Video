- 同一单值资产保持稳定幂等语义；
- OpenAPI公开`asset_id`且不公开`asset_ids`或其他内部资产结构；

## 6. F-02复验：公开参数强校验

### 6.1 规则来源和结构

确认：

- Router、Service、测试和文档没有形成相互漂移的多套规则；
- 公开文档中的参数表与真实Schema一致。

### 6.2 必测参数

逐类核验：

| 参数 | 预期核心约束 |
|---|---|
| `prompt` | 严格字符串、去空白后非空、1..4096、全部工作流必填 |
| `negative_prompt` | 严格字符串、0..4096、可选 |
| `width`、`height` | 严格整数、1..16384 |
| `frame_count` | 严格整数、1..10000 |
| `seed` | 严格整数、0..`2^64-1` |
| `steps` | 严格整数、1..1000、只适用于两个I2V |
| `cfg` | 严格有限浮点数、0..100、只适用于两个I2V |

至少独立确认：

- 最小值和最大值可接受；
- 低于最小值和高于最大值被拒绝；
- 字符串、对象、数组和布尔值不能冒充数字；
- 对象和数组不能冒充字符串；
- NaN、Infinity及非有限浮点被拒绝；
- 未知参数和当前工作流不适用参数被拒绝；
- 超长字符串和超过32 KiB的序列化参数体被拒绝；
- 首次验收的4个复现值全部返回422：
  - `width="not-an-integer"`
  - `prompt={"nested":"object"}`
  - `steps=-999`
  - `cfg="bad"`
- 每个无效请求后，真实临时Repository中的任务和幂等记录均为零。

注意检查Python/Pydantic中`bool`作为`int`子类、浮点NaN/Infinity、JSON解析行为及边界值是否存在绕过。

## 8. F-04复验：关键覆盖有效性

### 8.1 分页

使用真实API与临时Repository，创建足够数据跨至少3页，并令多条任务具有相同`created_at`，确认：

- 固定排序`created_at DESC, job_id DESC`；
- `limit + 1`只用于计算`has_more`，额外行不泄露；
- 3页之间无重复、无漏项；
- 中间页`has_more=true`，末页为`false`；
- 状态过滤与分页组合正确；
- `limit`为1..100，`offset`非负；
- 响应不包含精确`total`。

### 8.2 重试幂等及并发

至少独立复现同一失败原任务的8路并发重试，确认：

- 只产生一个子任务；
- 首次唯一创建最多一个`201`，其余为同一任务的`200`；
- 没有500、重复子任务或错误冲突；
- 创建与重试使用同一原始键相互隔离；
- 不同原任务使用同一原始键相互隔离；
- 子任务`retry_of_job_id`、`retry_count`和新任务标识正确；
- 原任务状态及字段不变；
- `submission_unknown`仍不可重试；
- 原任务读取、资格检查和子任务插入保持单一短事务语义。

### 8.3 服务不可用、OpenAPI和架构边界

确认：

- 服务不可用返回固定`503 service_unavailable`且不泄露原始原因；
- 5个操作的OpenAPI Schema无内部字段；
- Router导入不连接数据库、不迁移、不建表、不启动Worker或外部服务；
- Router不直接依赖旧`TaskManager`、Worker、Executor、ComfyUI或ORM业务流程；
- 旧`/api/tasks`及两个`/api/video/generate/*`入口仍注册且未改写；
